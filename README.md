# vibe-coding-review

`vibe-coding-review` 是一个 Codex Skill，用来把 AI 辅助编程项目沉淀成可复用的个人学习复盘。

它解决的问题很简单：AI 可以很快帮你把项目做出来，但如果每次结束后只留下代码、commit 和一堆聊天记录，你可能并没有真正变强。这个 skill 会帮你回看一个阶段或一个项目中发生了什么、为什么这样做、你如何指挥 AI、哪里验收不足、哪些问题正在重复出现，并生成一份适合放进 Obsidian 的 Markdown 复盘报告。

它不是普通项目总结器，也不是逐行讲代码的教程。它更像一个项目负责人复盘顾问，重点帮助你把一次 vibe coding 经历转化成下一次可复用的判断力。

## 适合谁

这个 skill 适合这些用户：

- 主要通过 Codex、Cursor、Trae、Claude Code 等 AI 编程工具做项目
- 不是传统程序员，但希望理解项目是怎么被做出来的
- 想复盘自己如何给 AI 下任务、控范围、验收结果
- 想把每个项目阶段沉淀成长期学习资产
- 想在多次项目之间追踪自己的重复问题和进步趋势

如果你只是想写 changelog、README、开发进度记录、交接文档或项目内部技术总结，不建议使用这个 skill。

## 它会生成什么

一次复盘会生成一份 Markdown 报告，通常包含：

- 证据盘点：当前窗口上下文、代码变化、文档、计划、日志、测试、验收证据
- 本阶段或完整项目到底做了什么
- 项目推进流程复盘
- 架构理解和关键模块地图
- AI 协作与指挥质量分析
- 产品或商业判断复盘
- 核心概念词典
- Debug 与返工复盘
- 六项评分卡
- 与上一份同项目复盘的趋势比较
- 重复问题标签与成因分析
- 项目理解行动作业
- 根据问题反推出的提示词优化方向

报告默认使用中文，适合直接放进 Obsidian、Notion 或任何 Markdown 笔记系统。

## 三种复盘模式

### 阶段复盘

适合在一个功能、一次迭代、一次调试、一次部署或一个阶段里程碑结束后使用。

阶段复盘会优先分析：

- 当前窗口完整上下文
- 范围内 diff
- 实施计划和 TODO
- 聊天决策
- 错误日志
- 验收或测试结果

它重点回答：这一阶段处在项目的什么位置、AI 实际做了什么、架构发生了什么变化、你哪里指挥得清楚或不清楚。

### 完整项目复盘

适合在项目完成、上线、交付、暂停或需要完整回顾时使用。

完整复盘会扩展到整个项目，分析项目发展路径、整体架构、关键技术决策、核心功能模块、产品成熟度、商业落地准备度、反复出现的问题和可复用经验。

### 月度复盘汇总

适合读取多份已有复盘报告，做月度总结。

月度汇总会比较多份报告中的评分变化、重复问题、未完成行动作业，以及你作为项目负责人的能力是否在提升。

## 当前窗口上下文规则

对 `阶段复盘` 和 `完整复盘`，这个 skill 会把当前窗口完整上下文当作一等证据，而不是只看最终 diff 或最后一次 commit。

这意味着报告会尽量读取并分析：

- 你的原始目标
- 你给 AI 的提示词约束
- 中途的范围变化
- AI 的计划和决策
- 工具调用、测试输出和错误日志
- 验收证据和未闭合问题

如果当前窗口上下文不可见、被截断或只能读取一部分，报告会把这个限制写进“证据边界”或“缺失证据”，而不是假装已经完整分析。

## 安装

把仓库克隆到 Codex 的 skills 目录：

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/PerpperQAQ/vibe-coding-review.git ~/.codex/skills/vibe-coding-review
```

然后重启 Codex，或按你的环境重新加载 skills。

## 输出目录

生成报告时，skill 会按下面顺序选择输出目录：

1. 使用你在请求中明确指定的目录
2. 使用环境变量 `VIBE_CODING_REVIEW_DIR` 指向的目录
3. 如果项目里已有 `docs/`、`notes/` 或 `reviews/`，创建对应的 `vibe-coding-reviews` 子目录
4. 否则在当前项目根目录创建 `vibe-coding-reviews/`

如果你使用 Obsidian，推荐把环境变量指向你的 vault 内部文件夹：

```bash
export VIBE_CODING_REVIEW_DIR="$HOME/Documents/Obsidian/Vibe coding reviews"
```

你也可以在提示词里直接指定目录：

```text
使用 $vibe-coding-review 给这个项目做一次个人阶段复盘，写入 /你的/Obsidian/Vibe coding复盘。
```

## 使用示例

阶段复盘：

```text
使用 $vibe-coding-review 给这个项目做一次个人阶段复盘。
范围：最近 3 次 commit 和当前窗口完整上下文。
请重点分析项目推进流程、架构变化、AI 指挥质量和验收结果。
```

完整项目复盘：

```text
使用 $vibe-coding-review 给这个项目做一次完整复盘。
重点关注开发流程、整体架构、AI 协作方式、产品成熟度、商业落地可能性和下次可复用经验。
```

月度复盘汇总：

```text
使用 $vibe-coding-review 基于这些复盘报告生成一份月度复盘汇总。
请比较评分变化、重复出现的问题、未完成行动作业，以及我作为项目负责人的能力变化。
```

指定输出目录：

```text
使用 $vibe-coding-review 复盘本阶段，报告写进我的 Obsidian 目录：/Users/me/Notes/Vibe coding复盘。
```

## 评分维度

报告固定使用六个评分维度，每项 1 到 10 分：

| 维度 | 关注点 |
|---|---|
| 项目推进清晰度 | 目标、范围、阶段边界、推进节奏是否清楚 |
| 架构理解程度 | 你是否理解项目结构、模块职责和关键流程 |
| AI 指挥质量 | 提示词是否清楚，是否给出约束、验收标准和禁止事项 |
| 产品判断质量 | 是否理解用户价值、功能闭环、商业或使用场景 |
| 验收与测试意识 | 是否用测试、截图、日志、用户路径证明结果 |
| 复利沉淀质量 | 是否把经验转成下次可复用的知识、标签和行动作业 |

如果找到同项目上一份复盘，报告还会比较评分趋势，说明哪些行为变好了、哪些问题仍在重复。

## 重复问题追踪

报告会用稳定标签追踪反复出现的问题，例如：

- `continue-next-stage-inertia`
- `vague-acceptance-criteria`
- `missing-user-path-validation`
- `weak-architecture-recall`
- `static-tests-over-real-validation`
- `overbroad-scope`
- `unclear-product-gate`

这些标签不是为了批评，而是为了让你看到自己在不同项目里是否一直踩同一种坑。

## 让复盘更准确的提示

你可以在请求里提供这些信息，让报告更准：

- 本次复盘范围，例如最近几次 commit、某个分支、某个阶段名
- 你希望写入的目录
- 项目目标或阶段目标
- 你认为最重要的验收标准
- 是否要和上一份同项目复盘比较
- 是否有截图、部署地址、PR、issue 或日志需要纳入

推荐请求格式：

```text
使用 $vibe-coding-review 给这个项目做一次个人阶段复盘。
范围：从 commit abc123 到当前 HEAD，以及当前窗口完整上下文。
输出目录：我的 Obsidian/Vibe coding复盘。
请重点看：阶段目标是否闭合、验收证据是否充分、我指挥 AI 的问题、下一阶段提示词应该怎么改。
```

## 仓库结构

```text
.
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    └── report-templates.md
```

- `SKILL.md`：skill 的核心触发边界、工作流、证据规则和写作规则
- `references/report-templates.md`：阶段复盘、完整复盘、月度汇总的报告模板
- `agents/openai.yaml`：Codex UI 展示信息

## 隐私提醒

复盘报告可能包含敏感信息。公开或分享报告前，请检查是否包含：

- 本地文件路径
- 聊天记录片段
- commit 信息
- 部署地址
- 产品想法或商业假设
- 错误日志
- 截图、PR 或 issue 信息
- API key、账号、客户数据等敏感内容

skill 会要求 Codex 不要编造缺失证据，也不要把证据边界说成已经验证。但具体项目材料能不能公开，仍需要你自己判断。

## 校验

如果你本地有 Codex skill creator 脚本，可以运行：

```bash
python3 /path/to/skill-creator/scripts/quick_validate.py ~/.codex/skills/vibe-coding-review
```

校验通过说明 skill 的基础结构合法，但不代表复盘质量已经在真实项目中充分验证。建议先用一个小范围阶段试跑，再根据报告质量继续迭代模板。
